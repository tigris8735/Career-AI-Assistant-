# Системный анализ и технические требования

## 🎯 Общее описание системы

Career AI Assistant - это двусторонняя платформа с двумя основными пользовательскими потоками:

### Для соискателей:
1. **Загружают резюме** → система анализирует и предлагает улучшения
2. **Ищут вакансии** → AI подбирает наиболее релевантные
3. **Адаптируют резюме** → автоматическая кастомизация под каждую вакансию
4. **Готовятся к собеседованию** → AI-симулятор и рекомендации
5. **Отслеживают прогресс** → аналитика и уведомления

### Для HR и рекрутеров:
1. **Загружают вакансии** → система анализирует требования
2. **Получают кандидатов** → AI ранжирует по релевантности
3. **Анализируют резюме** → глубокая аналитика навыков и опыта
4. **Сравнивают кандидатов** → объективная оценка компетенций
5. **Управляют процессом** → автоматизация коммуникации

## 🔧 Функциональные требования

### Модуль 1: Профили пользователей
**FR-1.1:** Двойная система регистрации
- Для соискателей: email, пароль, основные данные
- Для HR/компаний: данные компании, контакты, потребности

**FR-1.2:** Раздельные личные кабинеты
- Dashboard для соискателей: прогресс поиска, статистика
- Dashboard для HR: активные вакансии, кандидаты, метрики

### Модуль 2: Анализ и обработка резюме
**FR-2.1:** Универсальный парсинг резюме
- Поддержка PDF, DOCX, DOC, TXT
- Извлечение структурированных данных для обоих типов пользователей
- Поддержка русского и английского языков

**FR-2.2:** Для соискателей:
- Рекомендации по улучшению резюме
- Анализ соответствия требованиям рынка
- Обнаружение пробелов в навыках

**FR-2.3:** Для HR:
- Быстрый анализ множества резюме
- Выявление ключевых компетенций
- Обнаружение "красных флагов"

### Модуль 3: Работа с вакансиями
**FR-3.1:** Для соискателей:
- Умный поиск по тысячам вакансий
- Персонализированные рекомендации
- Анализ требований и зарплатных ожиданий

**FR-3.2:** Для HR:
- Публикация вакансий с AI-анализом
- Автоматическое обновление требований
- Анализ конкурентных предложений

### Модуль 4: Сопоставление и матчинг
**FR-4.1:** Двусторонний матчинг:
- Соискатель → Вакансия: рейтинг совпадения, рекомендации
- Вакансия → Кандидат: ранжирование кандидатов, прогноз успеха

**FR-4.2:** Продвинутые алгоритмы:
- Учет hard и soft skills
- Анализ культурного соответствия
- Прогноз успешности найма

### Модуль 5: Коммуникация и взаимодействие
**FR-5.1:** Для соискателей:
- AI-чат для подготовки к собеседованиям
- Шаблоны сопроводительных писем
- Автоматические отклики на вакансии

**FR-5.2:** Для HR:
- Автоматизированные рассылки кандидатам
- Шаблоны писем с обратной связью
- Календарь собеседований с интеграцией

### Модуль 6: Аналитика и отчетность
**FR-6.1:** Для соискателей:
- Прогресс поиска работы
- Статистика откликов и ответов
- Рекомендации по улучшению профиля

**FR-6.2:** Для HR:
- Метрики эффективности подбора
- Анализ источников кандидатов
- Отчеты по времени и стоимости найма

## 🛡️ Нефункциональные требования

### Производительность
**NFR-1:** Время отклика системы
- Загрузка и анализ резюме: < 30 секунд
- Поиск вакансий: < 5 секунд
- AI-ответы в чате: < 10 секунд
- Массовая обработка резюме для HR: < 2 минут на 100 резюме

**NFR-2:** Пропускная способность
- Одновременных пользователей: 5000
- Резюме в обработке: 200/минуту
- API запросы к HH.ru: 100/секунду

### Масштабируемость
**NFR-3:** Горизонтальное масштабирование
- Отдельные инстансы для соискателей и HR
- Микросервисная архитектура
- Кэширование частых запросов

### Безопасность
**NFR-4:** Разделение данных
- Строгая изоляция данных соискателей и компаний
- Шифрование конфиденциальной информации
- Ролевая модель доступа

**NFR-5:** Соответствие законодательству
- GDPR для международных пользователей
- 152-ФЗ для российских пользователей
- Соблюдение правил платформ (HH.ru, LinkedIn)

## 📊 Модель данных

### Основные сущности
```yaml
User:
  id: UUID
  type: enum(seeker, hr, company_admin)
  email: string
  subscription: JSON
  created_at: datetime

SeekerProfile:
  user_id: UUID
  resumes: array[Resume]
  skills: array[string]
  preferences: JSON
  job_search_status: enum(active, passive, not_looking)

HrProfile:
  user_id: UUID
  company_id: UUID
  role: enum(recruiter, hr_manager, admin)
  permissions: JSON

Company:
  id: UUID
  name: string
  industry: string
  size: enum(startup, small, medium, large)
  subscription_tier: enum(starter, business, enterprise)

Resume:
  id: UUID
  owner_type: enum(seeker, hr_uploaded)
  owner_id: UUID
  parsed_data: JSON
  skills: array[string]
  experience: JSON
  is_public: boolean

Vacancy:
  id: UUID
  posted_by: UUID (company_id)
  source: enum(hh_ru, linkedin, internal)
  requirements: JSON
  status: enum(active, closed, draft)
  candidates: array[MatchResult]

MatchResult:
  id: UUID
  vacancy_id: UUID
  resume_id: UUID
  match_score: float
  score_details: JSON
  status: enum(new, reviewed, contacted, rejected, hired)
  predicted_success: float
```

## 🔗 Интеграции

### Внешние сервисы
1. **HH.ru API** - для соискателей (поиск вакансий), для HR (публикация вакансий)
2. **LinkedIn API** - расширение возможностей поиска
3. **Платежные системы** - ЮKassa, Stripe для разных типов подписок
4. **Email сервисы** - SendGrid для уведомлений
5. **Календари** - Google Calendar, Outlook для собеседований

### API спецификации
- **RESTful API** с версионированием
- **Раздельные эндпоинты** для соискателей и HR
- **Rate limiting** в зависимости от подписки
- **OpenAPI 3.0** документация

## 🧪 Технологический стек

### Бэкенд
- **Фреймворк:** FastAPI (Python 3.11+)
- **База данных:** PostgreSQL 15 (основная), Redis (кэш)
- **Очереди:** Celery + RabbitMQ для асинхронных задач
- **Хранилище файлов:** MinIO/S3
- **ML/Аналитика:** scikit-learn, spaCy, трансформерные модели

### Фронтенд
- **Основной:** Vue.js 3 + Vite
- **UI библиотеки:** Element Plus (для соискателей), Ant Design Vue (для HR)
- **State management:** Pinia
- **Мобильная версия:** PWA с offline-возможностями

### DevOps
- **Контейнеризация:** Docker + Docker Compose
- **CI/CD:** GitHub Actions
- **Мониторинг:** Prometheus + Grafana + Loki
- **Хостинг:** Kubernetes для продакшена

## ⚡ Ограничения и допущения

### Функциональные ограничения
1. **Начальная география:** Россия, затем СНГ
2. **Языки:** русский, затем английский
3. **Форматы резюме:** PDF, DOCX, TXT
4. **Интеграции:** HH.ru → LinkedIn → другие

### Бизнес-ограничения
1. **Ценообразование:** гибкое для разных сегментов
2. **Юридические вопросы:** разные для соискателей и компаний
3. **Конкуренция:** разные конкуренты для двух сегментов

### Допущения
1. Соискатели готовы платить за качественный сервис
2. Компании готовы автоматизировать рекрутинг
3. Платформы (HH.ru) будут поддерживать API доступ
4. AI-технологии будут развиваться и становиться лучше
