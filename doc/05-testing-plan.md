
# План тестирования

## 🎯 Общие сведения

**Проект:** AI HR Assistant  
**Версия тестового плана:** 1.0  
**Дата:** Q1 2024  
**Ответственные:** QA Team, DevOps, Разработчики

## 📋 Область тестирования

### Включаемые модули:
1. **Backend API** - все REST эндпоинты
2. **Frontend SPA** - пользовательский интерфейс
3. **ML Pipeline** - обработка и анализ данных
4. **Интеграции** - внешние сервисы (HH.ru, LLM провайдеры)
5. **Производительность** - нагрузочное тестирование
6. **Безопасность** - пентест и аудит безопасности

### Исключаемые модули:
1. Код внешних сервисов (HH.ru, LLM провайдеры)
2. Инфраструктура хостинг-провайдеров
3. Сторонние библиотеки и зависимости

## 🧪 Типы тестирования

### 1. Модульное тестирование (Unit Testing)
**Цель:** Проверка отдельных компонентов и функций
**Покрытие:** ≥ 80% кода бэкенда
**Инструменты:** pytest, unittest, coverage.py

### 2. Интеграционное тестирование
**Цель:** Проверка взаимодействия между модулями
**Сценарии:** API эндпоинты, работа с БД, интеграции

### 3. Системное тестирование (E2E)
**Цель:** Проверка всей системы как единого целого
**Сценарии:** Полные пользовательские сценарии

### 4. Нагрузочное тестирование
**Цель:** Проверка производительности под нагрузкой
**Инструменты:** locust, k6, JMeter

### 5. Тестирование безопасности
**Цель:** Выявление уязвимостей
**Инструменты:** OWASP ZAP, Burp Suite, Bandit

### 6. Тестирование удобства использования (UX)
**Цель:** Проверка пользовательского опыта
**Методы:** Юзабилити тестирование, A/B тесты

## 📋 Тестовые сценарии

### Модуль: Аутентификация
```gherkin
Feature: Аутентификация пользователя

  Scenario: Успешная регистрация нового пользователя
    Given Пользователь находится на странице регистрации
    When Он заполняет все обязательные поля корректно
    And Нажимает кнопку "Зарегистрироваться"
    Then Пользователь получает подтверждение по email
    And Перенаправляется на страницу подтверждения

  Scenario: Неуспешная регистрация с существующим email
    Given Пользователь с email "test@example.com" уже существует
    When Пользователь пытается зарегистрироваться с тем же email
    Then Система показывает ошибку "Email уже зарегистрирован"
    And Форма не отправляется
```

### Модуль: Загрузка и анализ резюме
```gherkin
Feature: Загрузка и анализ резюме

  Scenario: Успешная загрузка PDF резюме
    Given Пользователь авторизован в системе
    And Находится на странице загрузки резюме
    When Он выбирает PDF файл с резюме
    And Заполняет название резюме
    And Нажимает кнопку "Загрузить"
    Then Файл загружается на сервер
    And Запускается процесс анализа
    And Пользователь видит индикатор прогресса
    And После завершения видит результат анализа

  Scenario: Загрузка файла неподдерживаемого формата
    Given Пользователь авторизован в системе
    When Он пытается загрузить файл с расширением .jpg
    Then Система показывает ошибку "Неподдерживаемый формат файла"
    And Файл не загружается
```

## ⚡ Нагрузочное тестирование

### Сценарии нагрузки:
```javascript
// k6 тест для API
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '30s', target: 10 },    // Разогрев
    { duration: '1m', target: 50 },     // Средняя нагрузка
    { duration: '30s', target: 100 },   // Пиковая нагрузка
    { duration: '30s', target: 0 },     // Снижение
  ],
  thresholds: {
    http_req_duration: ['p(95)<2000'],  // 95% запросов < 2 сек
    http_req_failed: ['rate<0.01'],     // < 1% ошибок
  },
};

export default function() {
  const BASE_URL = 'https://api.hr-assistant.example.com';
  
  // Регистрация пользователя
  const registerRes = http.post(`${BASE_URL}/api/v1/auth/register`, {
    email: `test${__VU}@example.com`,
    password: 'TestPass123!',
    full_name: `Test User ${__VU}`,
  });
  
  check(registerRes, {
    'register status 201': (r) => r.status === 201,
  });
  
  sleep(1);
}
```

## 📊 Критерии завершения тестирования

### Тестирование считается завершенным когда:
1. Все критические и блокирующие дефекты исправлены
2. Покрытие тестами ≥ 80% для backend, ≥ 70% для frontend
3. Все основные пользовательские сценарии протестированы
4. Производительность соответствует требованиям
5. Отчеты безопасности не содержат критичных уязвимостей
6. Документация по тестированию обновлена
7. Команда продукта подтвердила приемку

### Exit Criteria:
- **Zero** критических дефектов
- **≤ 5** мажорных дефектов
- **≤ 10** минорных дефектов
- Производительность: p95 < 2s
- Доступность: 99.5% во время тестирования
