# План разработки бэкенда AI Career Scout
## Задача BE-1: Инициализация проекта и базовая архитектура
**Название:** Создать базовую структуру FastAPI-проекта с Docker и конфигурацией.

**Описание:**

**Цель (Relevant):** Заложить основу для всего бэкенда. Без этой задачи невозможна разработка других модулей.

**Контекст (Specific):** Создать репозиторий, настроить pyproject.toml с зависимостями (FastAPI, SQLAlchemy, Pydantic, Alembic, psycopg2). Написать Dockerfile и docker-compose.yml для запуска сервиса и БД PostgreSQL. Реализовать конфигурацию через .env и Pydantic-settings.

**Ресурсы/Условия (Achievable):** Утвержденный стек технологий. Доступ к Git-репозиторию, Docker, Python 3.11+.

**Критерии приемки (Measurable):**

- Проект клонируется и запускается одной командой: docker-compose up --build.

- Контейнеры app и postgres_db работают.

- По адресу http://localhost:8000/docs доступна пустая страница Swagger UI.

- Все зависимости зафиксированы в requirements.txt или poetry.lock.

**Ответственный:** [Бэкенд-лид / Senior Backend]
**Сроки (Time-bound):**

**Начало:** 01.04.2024

**Трудоемкость:** 1 рабочий день

**Дедлайн:** 01.04.2024, 18:00
**Связь:** Блокирует все последующие бэкенд-задачи.

## Задача BE-2: Разработка моделей данных и миграций (SQLAlchemy + Alembic)
**Название:** Реализовать core-модели и настроить систему миграций БД.

**Описание:**

**Цель (Relevant):** Определить и создать структуру данных для хранения информации о пользователях, резюме, вакансиях и навыках.

**Контекст (Specific):** Создать модели SQLAlchemy: User, Resume, Vacancy, Skill, TestResult, TestQuestion. Настроить связи (one-to-many, many-to-many). Инициализировать Alembic, создать первую миграцию для генерации схемы БД.

**Ресурсы/Условия (Achievable):** Готовая техническая спецификация с описанием сущностей. Работающий контейнер с PostgreSQL (из BE-1).

## Задача BE-3: Реализация CRUD API для управления пользователями и аутентификации
**Название:** Создать эндпоинты для регистрации, логина и управления профилем.

**Описание:**

**Цель (Relevant):** Обеспечить базовую функциональность системы - работу с аккаунтами. Без этого пользователи не смогут войти.

**Контекст (Specific):** Реализовать эндпоинты: POST /auth/register, POST /auth/login, GET /users/me, PATCH /users/me. Интегрировать JWT-аутентификацию. Добавить хеширование паролей (bcrypt). Настроить dependency injection для получения текущего пользователя.

**Ресурсы/Условия (Achievable):** Готовые модели User (из BE-2). Решение по методу аутентификации (JWT) утверждено.

**Критерии приемки (Measurable):**

- Регистрация создает нового пользователя в БД (пароль хешируется).

- Логин возвращает валидный access_token.

- Запрос к GET /users/me с токеном возвращает данные текущего пользователя.

- Неаутентифицированный запрос к защищенному эндпоинту возвращает 401.

- Написаны интеграционные тесты для всех сценариев.

**Ответственный:** [Бэкенд-разработчик]
**Сроки (Time-bound):**

**Начало:** 04.04.2024 *(зависит от BE-2)*

**Трудоемкость:** 2 рабочих дня

**Дедлайн:** 05.04.2024, 18:00

## Задача BE-4: Разработка модуля интеграции с HH.ru API
**Название:** Создать клиент и сервис для получения вакансий с HH.ru.

**Описание:**

**Цель (Relevant):** Обеспечить приток исходных данных (вакансий) в систему для последующей AI-обработки.

**Контекст (Specific):** Создать класс-клиент для работы с публичным API HH.ru (api.hh.ru). Реализовать методы поиска вакансий по параметрам. Парсить ответ API и сохранять в модель Vacancy. Добавить фоновую задачу (например, через Celery) для периодического обновления вакансий. Реализовать базовое кэширование (Redis).

**Ресурсы/Условия (Achievable):** Документация HH.ru API. Модель Vacancy (из BE-2). Доступ к Redis (в Docker).

**Критерии приемки (Measurable):**

- Эндпоинт POST /vacancies/fetch с параметрами {"text": "Python", "area": 1} возвращает список вакансий.

- Данные каждой вакансии сохраняются в БД (дубликаты не создаются).

- При превышении лимита запросов (429) реализован exponential backoff.

- Написаны unit-тесты для клиента HH.ru (с моками ответов).

**Ответственный:** [Бэкенд-разработчик]
**Сроки (Time-bound):**

**Начало:** 04.04.2024 *(зависит от BE-2, может выполняться параллельно с BE-3)*

## Задача BE-5: Модуль загрузки и парсинга резюме (PDF/DOCX)

Интегрировать библиотеки для парсинга текста (pdfplumber, python-docx). Написать простой парсер для извлечения ключевых полей: имя, опыт, навыки (пока по ключевым словам). ## Задача BE-6: Разработка ядра AI-верификации навыков (Интеграция с DeepSeek API)
**Название:** Создать сервис генерации тестов и оценки ответов через LLM.

**Описание:**

**Цель (Relevant):** Реализовать ключевую фичу продукта - объективную оценку уровня навыков.

**Контекст (Specific):** Разработать AIVerificationService. Реализовать промпты для: а) генерации теоретических вопросов и практических кейсов по навыку, б) оценки ответа пользователя по шкале 1-10. Интегрировать DeepSeek API (официальный SDK или httpx). Создать модели TestQuestion, TestResult. Реализовать логику определения общего уровня (Junior/Middle/Senior) на основе оценок.

**Ресурсы/Условия (Achievable):** API-ключ DeepSeek. Промпты согласованы с экспертом. Модели данных (из BE-2). Работающий парсер резюме (BE-5).

**Критерии приемки (Measurable):**

- Эндпоинт POST /verify/generate-test для навыка "Python" возвращает 1 вопрос и 1 кейс.

- Эндпоинт POST /verify/evaluate-answer возвращает оценку (число от 1 до 10) и развернутый фидбэк от LLM.

- Полный цикл тестирования по 3 навыкам сохраняет итоговый уровень в профиле пользователя.

- P95-латентность запроса к DeepSeek API < 20 секунд.

**Ответственный:** [Python-разработчик / ML Engineer]
**Сроки (Time-bound):**

**Начало:** 12.04.2024 *(зависит от BE-5)*

**Трудоемкость:** 5 рабочих дней

**Дедлайн:** 18.04.2024, 18:00
**Связь:** Зависит от BE-5. Является ключевым модулем.

## Задача BE-7: Модуль интеллектуальной фильтрации и ранжирования вакансий
**Название:** Реализовать AI-фильтрацию "шумных" вакансий и ранжирование по релевантности.

**Описание:**

**Цель (Relevant):** Повысить качество выдачи вакансий для пользователя, убрав проплаченные/нерелевантные предложения.

**Контекст (Specific):** Разработать VacancyFilterService. Написать промпты для DeepSeek API для анализа текста вакансии на: релевантность навыкам пользователя, признаки "фейковости", четкость требований. Реализовать скоринг вакансий (0-100%). Создать эндпоинт GET /vacancies/recommended с пагинацией и сортировкой по релевантности. Добавить кэширование результатов.

**Ресурсы/Условия (Achievable):** Данные о пользователе и его навыках (из BE-5, BE-6). База вакансий (из BE-4). Дополнительные промпты для LLM.

**Критерии приемки (Measurable):**

- Для пользователя с навыками ["Python", "FastAPI"] система помечает вакансию "Уборщик офиса" как нерелевантную (скор < 10%).

- Эндпоинт GET /vacancies/recommended возвращает отсортированный список.

- Написаны интеграционные тесты с моком LLM.
